# Bounded panels and repeats

Use only the explicitly accepted panel size and run count. Default to two personas
and one exploratory run; offer more only when a specific unresolved question
justifies cost. Never grow the panel merely to reach an apparent saturation score.
Use separate fresh contexts where the runtime supports them, with no browser or
network access delegated to personas. The coordinator owns actual UI observations.

Sources define roles and constraints; missing traits are assumptions. Resample
when the user requests another run, preserving its immutable snapshot. Report
repeat counts descriptively, alongside contradictory and one-off observations.
Counts are not population estimates, confidence intervals, statistical error bars
or proof of market validation. A repeated model answer is still a hypothesis.

Adversarial mode asks for grounded objections; it never discards agreement or
forces a refusal. Stop at the approved budget. Pair every useful hypothesis with
a real interview or data check that could refute it. Keep legacy output fields
but describe saturation as not established; do not infer real-user saturation
from model repetition. A single run carries exploratory observations only.
